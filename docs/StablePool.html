StablePool

is a generational object pool providing $O(1)$ allocation and stable references via generational handles.

Identity vs Validity

StablePool uses carp-handle to provide stable references. A handle is valid only if the pool hasn't reused its slot for a newer object.

Generation Wraparound

Generations use a Uint32. Upon overflow (~4 billion reuses), an old handle could theoretically resolve to a new object. This is considered acceptable risk for systems-grade performance.

Performance

Allocation and deallocation are $O(1)$ amortized. Access via handle is $O(1)$. Iteration is $O(N)$ where N is the total capacity.

                        (get-ptr p h)

returns a pointer to the element wrapped in a Maybe. Returns Nothing if the handle is stale or invalid.

Safety

The returned pointer is only valid as long as:

  1. The handle remains valid (the object has not been freed or reused).
  2. The pool has not grown (reallocated its internal buffer).
  3. The pool has not been cleared.
